# 🧪 Руководство по тестированию фаз

## Обзор

Это руководство поможет вам убедиться, что команда `/api/phases/next` последовательно проходит все нужные фазы.

## 🎯 Цель тестирования

Проверить, что:
1. **Последовательность фаз корректна** для разных ходов
2. **Переходы между фазами работают** через API
3. **Записи фаз сохраняются** в базе данных
4. **Переименование pursuit → shadow** выполнено корректно

## 📋 Тестовые сценарии

### Сценарий 1: Unit-тест логики фаз
```bash
# Запуск unit-теста (не требует сервера)
go run test_phase_sequence_unit.go
```

**Что проверяет:**
- ✅ Последовательность фаз для хода 1: `movement → search → air_attack → naval_combat → chance → admin`
- ✅ Последовательность фаз для хода 2+: `visibility → shadow → movement → search → air_attack → naval_combat → chance → admin`
- ✅ Переименование `pursuit` → `shadow`
- ✅ Симуляция переходов между фазами

### Сценарий 2: API-тест с сервером
```bash
# 1. Запустите сервер
go run cmd/server/main.go

# 2. В другом терминале запустите API-тест
go run test_phase_api.go
```

**Что проверяет:**
- ✅ Создание игры
- ✅ Начало хода
- ✅ Последовательный переход по фазам через `/api/phases/next`
- ✅ Проверка текущей фазы через `/api/phases/current`
- ✅ Получение записей фаз через `/api/phases/records`

### Сценарий 3: Ручная проверка через curl
```bash
# Запустите сервер
go run cmd/server/main.go

# В другом терминале запустите скрипт
./check_phases.sh
```

**Что проверяет:**
- ✅ Доступность сервера
- ✅ Создание игры через API
- ✅ Ручной переход по фазам
- ✅ Проверка каждой фазы

## 🔍 Детальная проверка

### 1. Проверка последовательности для хода 1
```bash
curl -X POST http://localhost:8080/api/phases/start-turn \
  -H "Content-Type: application/json" \
  -d '{"game_id": "test-game-1"}'
```

**Ожидаемая последовательность:**
1. `movement` (начальная фаза)
2. `search` (после `/api/phases/next`)
3. `air_attack` (после `/api/phases/next`)
4. `naval_combat` (после `/api/phases/next`)
5. `chance` (после `/api/phases/next`)
6. `admin` (после `/api/phases/next`)

### 2. Проверка последовательности для хода 2+
```bash
# После завершения хода 1, начинается ход 2
```

**Ожидаемая последовательность:**
1. `visibility` (начальная фаза)
2. `shadow` (после `/api/phases/next`) - **переименовано из pursuit**
3. `movement` (после `/api/phases/next`)
4. `search` (после `/api/phases/next`)
5. `air_attack` (после `/api/phases/next`)
6. `naval_combat` (после `/api/phases/next`)
7. `chance` (после `/api/phases/next`)
8. `admin` (после `/api/phases/next`)

### 3. Проверка API endpoints

#### Получение текущей фазы
```bash
curl "http://localhost:8080/api/phases/current?game_id=test-game-1"
```

#### Переход к следующей фазе
```bash
curl -X POST http://localhost:8080/api/phases/next \
  -H "Content-Type: application/json" \
  -d '{"game_id": "test-game-1"}'
```

#### Получение записей фаз
```bash
curl "http://localhost:8080/api/phases/records?game_id=test-game-1"
```

## 🚨 Возможные проблемы

### Проблема 1: Сервер не запущен
```
❌ Ошибка: connection refused
```
**Решение:** Запустите сервер командой `go run cmd/server/main.go`

### Проблема 2: Неправильная последовательность фаз
```
❌ Неожиданная фаза: ожидалось movement, получено search
```
**Решение:** Проверьте логику в `models.GetPhaseSequence()`

### Проблема 3: Фаза pursuit не переименована
```
❌ Проблема с переименованием: shadow=false pursuit=true
```
**Решение:** Проверьте константы в `models/phases.go`
