# Техническое задание: Реализация обнаружения вражеских кораблей в фазе поиска

## 1. Общее описание

Реализовать автоматическое обнаружение вражеских кораблей и Task Forces в фазе поиска на основе факторов поиска и уровня видимости.

## 2. Условия запуска фазы поиска

### 2.1. Предварительные проверки

Перед началом обработки поиска выполнить следующие проверки:

1. **Уровень видимости X (максимальный):**
   - Если `visibility_level >= 10` → фазу завершить сразу
   - Поиск полностью заблокирован
   - Никакие маркеры обнаружения не устанавливаются

### 2.2. Порядок обработки

Обработка поиска выполняется **последовательно для каждой стороны**:

1. **Сначала союзники** ищут немецкие юниты
2. **Затем немцы** ищут союзные юниты

Это гарантирует, что каждая сторона видит результаты своего поиска независимо.

## 3. Алгоритм обнаружения

### 3.1. Источник данных для поиска

**Использовать GameModel.Search:**
- Данные уже рассчитаны и сохранены в `GameModel.Search.German` и `GameModel.Search.Allied`
- Каждая сторона имеет мапу `map[string]SearchHexData`, где:
  - Ключ: `hex_id` (идентификатор гекса)
  - Значение: `SearchHexData` (структура с рассчитанными факторами)

**Структура SearchHexData:**
```go
type SearchHexData struct {
    Factor    int // ships*1 + patrol*3 + air_search*2 + intrinsic (уже рассчитано)
    Ships     int // количество кораблей и ТФ
    Patrol    int // количество маркеров патруля
    AirSearch int // количество маркеров воздушного поиска (flight_path_search)
    Intrinsic int // собственные факторы поиска гекса
}
```

### 3.2. Определение гексов для поиска

Для каждой стороны использовать соответствующий раздел `GameModel.Search`:

```
Для союзной стороны:
    Использовать GameModel.Search.Allied (map[string]SearchHexData)

Для немецкой стороны:
    Использовать GameModel.Search.German (map[string]SearchHexData)
```

**Алгоритм обработки:**

```
Для каждой записи (hex_id, searchHexData) в GameModel.Search.[Allied|German]:
    1. Проверить, что searchHexData.Factor >= visibility_level
       - Если нет → пропустить гекс (недостаточно факторов)
    2. Если условие выполнено:
       → Обработать гекс (найти вражеские юниты и установить DetectionLevel)
```

**Важно:** Все гексы из GameModel.Search, где Factor >= visibility_level, должны быть обработаны. Туманные гексы не должны попадать в GameModel.Search (фильтрация выполняется ранее).

**Важно:**
- Факторы уже рассчитаны в `SearchHexData.Factor`
- Не требуется дополнительный вызов `CalculateSearchFactors`
- Гексы с нулевыми факторами отсутствуют в мапе (оптимизация хранения)

### 3.3. Обработка каждого гекса с достаточными факторами

Для каждого гекса из `GameModel.Search.[Allied|German]`, где `SearchHexData.Factor >= visibility_level`:

```
1. Получить SearchHexData для гекса из GameModel.Search.[Allied|German][hex_id]

2. Найти все вражеские юниты и ТФ в гексе:
   - Одиночные корабли противника (национальность != сторона ищущего игрока)
   - Task Forces противника

3. Определить DetectionLevel на основе SearchHexData:
   - Если SearchHexData.AirSearch > 0 (есть маркеры flight_path_search):
     → DetectionLevel = SHADOWED
   - Иначе:
     → DetectionLevel = SIGHTED

4. Обновить данные:
   - Для каждого корабля: обновить `naval_units.detection_level`
   - Для каждой ТФ: обновить `task_forces.detection_level`
   - Для каждого юнита в ТФ: также обновить `naval_units.detection_level`

5. Обновить таблицу видимости:
   - Вызвать VisibilityService.SetUnitSighted() или SetUnitShadowed()
   - Сохранить гекс обнаружения и время
```

**Важно:**
- Использовать `SearchHexData.AirSearch` для проверки наличия маркеров воздушного поиска
- Не требуется дополнительный запрос к базе данных для проверки маркеров

### 3.4. Особые случаи

1. **Гекс без вражеских юнитов:**
   - Поиск выполнен успешно, но контактов не обнаружено
   - Никакие маркеры не устанавливаются
   - Логировать: `Search «hex <HEX_ID>: нет контакта»`

2. **Гекс с несколькими вражескими юнитами/ТФ:**
   - Все найденные объекты получают одинаковый DetectionLevel
   - Если есть хотя бы один маркер воздушного поиска → все получают SHADOWED
   - Иначе → все получают SIGHTED

3. **Смешанный случай (одиночные корабли + ТФ):**
   - Все обрабатываются одинаково
   - Маркеры выставляются на всё обнаруженное

## 4. Определение DetectionLevel

### 4.1. Правило установки

Использовать данные из `SearchHexData` для гекса:

```
ЕСЛИ SearchHexData.AirSearch > 0 (есть маркеры flight_path_search):
    DetectionLevel = SHADOWED (для всех кораблей и ТФ противника в гексе)
ИНАЧЕ:
    DetectionLevel = SIGHTED (для всех кораблей и ТФ противника в гексе)
```

**Важно:**
- Использовать `SearchHexData.AirSearch` из `GameModel.Search.[Allied|German][hex_id]`
- Не требуется дополнительный запрос к базе данных для проверки маркеров
- Если `AirSearch > 0`, то в гексе есть хотя бы один маркер `flight_path_search`
- Все обнаруженные объекты в гексе получают одинаковый DetectionLevel

### 4.2. Обработка кораблей в Task Force

Если обнаруженная ТФ имеет `DetectionLevel = SHADOWED` или `SIGHTED`, то:
- Все корабли, входящие в эту ТФ, также получают тот же `DetectionLevel`
- Обновление выполняется для каждого корабля отдельно

## 5. Удаление маркеров воздушного поиска

**В конце фазы поиска** (после обработки всех гексов для обеих сторон):

- Удалить **все** маркеры `flight_path_search` у обеих сторон
- Маркеры удаляются независимо от результатов поиска
- Это гарантирует, что маркеры не переносятся на следующий ход

## 6. Логирование

### 6.1. Сообщения для ищущей стороны

Для каждого гекса с обнаруженными контактами:
```
Search «hex <HEX_ID>: обнаружено <N> корабля(ей) (<CLASS×COUNT>, …). Task force: <TF_NAME|нет>. Detection=<SIGHTED|SHADOWED>»
```

Для гексов без контактов:
```
Search «hex <HEX_ID>: нет контакта»
```

### 6.2. Предупреждения для владеющей стороны

Для одиночных кораблей:
```
Search warning «hex <HEX_ID>: противник обнаружил <SHIP_NAME_1>, <SHIP_NAME_2>, … Detection=<SIGHTED|SHADOWED>»
```

Для Task Force:
```
Search warning «hex <HEX_ID>: противник обнаружил нашу TF <TF_NAME> (<SHIP_NAME_1>, <SHIP_NAME_2>, …). Detection=<SIGHTED|SHADOWED>»
```

### 6.3. Логирование переходов DetectionLevel

При установке или изменении DetectionLevel:
```
Detection «<TYPE> <NAME>: status <FROM> → <TO> (hex <HEX_ID>, turn <TURN>)»
```

Для владельца:
```
Detection warning «hex <HEX_ID>: наш <TYPE> <NAME> перешёл в статус <TO>»
```

## 7. Снятие маркеров обнаружения

### 7.1. В фазе видимости (Visibility Phase)

**При тумане (`is_fog = true`):**
- Убрать все маркеры `SIGHTED` и `SHADOWED` у кораблей и ТФ в **туманных гексах**
- Использовать `MapStructureService.GetFogHexes()` для получения списка туманных гексов
- Установить `DetectionLevel = NONE` для всех юнитов/ТФ в туманных гексах

**При видимости X (`visibility_level >= 10`):**
- Убрать **все** маркеры `SIGHTED` и `SHADOWED` независимо от гекса
- Установить `DetectionLevel = NONE` для всех юнитов и ТФ

### 7.2. В конце фазы движения (Movement Phase Complete)

**Автоматический переход:**
- Все `SHADOWED` → `SIGHTED` (через `UnitService.ConvertShadowedToSighted`)
- Это происходит для всех кораблей и ТФ автоматически

**Дополнительно - проверка тумана:**
- Если корабль/ТФ с `DetectionLevel = SHADOWED` находится в туманном гексе:
  - Установить `DetectionLevel = NONE` (сбросить обнаружение)
  - Это выполняется через `ResetDetectionForUnitsInFog`

### 7.3. В конце фазы преследования (Shadow Phase Complete)

**Очистка оставшихся SIGHTED:**
- После всех попыток преследования:
  - Оставшиеся `SIGHTED` (которые не стали `SHADOWED`) → `NONE`
  - Выполняется через `UnitService.RemoveRemainingSighted`
- `SHADOWED` остаются без изменений

**Логика:**
- Если в фазе преследования `SIGHTED` стал `SHADOWED` → сохраняется
- Если `SIGHTED` не подвергался преследованию или преследование провалилось → сбрасывается в `NONE`

## 8. Последовательность операций в фазе поиска

```
1. Предварительные проверки:
   - Загрузить GameModel для игры
   - Проверить visibility_level (если >= 10 → завершить)

2. Обработка союзной стороны:
   - Получить GameModel.Search.Allied (map[string]SearchHexData)
   - Для каждой записи (hex_id, searchHexData):
     * Проверить searchHexData.Factor >= visibility_level
     * Если условие выполнено:
       - Найти вражеские (немецкие) юниты и ТФ в гексе
       - Проверить searchHexData.AirSearch > 0 для определения DetectionLevel
       - Установить DetectionLevel (SHADOWED если AirSearch > 0, иначе SIGHTED)
       - Обновить видимость для всех найденных юнитов и ТФ
       - Логировать результаты

3. Обработка немецкой стороны:
   - Получить GameModel.Search.German (map[string]SearchHexData)
   - Аналогично шагу 2, но ищутся союзные юниты

4. Завершение фазы:
   - Удалить все маркеры flight_path_search
   - Синхронизировать состояние с VisibilityService
```

**Важные моменты:**
- Данные берутся из GameModel.Search, не из базы данных
- Факторы поиска уже рассчитаны и хранятся в SearchHexData.Factor
- Маркеры воздушного поиска определяются через SearchHexData.AirSearch
- Все гексы в GameModel.Search должны быть обработаны (туманные гексы не должны попадать в Search)

## 9. Интеграция с другими системами

### 9.1. GameStateService

Использовать для получения GameModel:
- `LoadGameModel(gameID)` - для загрузки GameModel с актуальными данными Search
- `GameModel.Search.German` и `GameModel.Search.Allied` - уже содержат все необходимые данные

**Важно:** Данные в GameModel.Search должны быть актуализированы перед фазой поиска через:
- `RecalculateSearchDataForAllRelevantHexes()` - пересчет факторов поиска для всех релевантных гексов
- Это должно выполняться автоматически при изменении позиций юнитов, маркеров и т.д.

### 9.2. SearchService (опционально)

Может потребоваться для:
- `RemoveAllFlightPathSearchMarkers(gameID)` - удаление маркеров в конце фазы
- Для проверки маркеров в процессе работы (если нужна дополнительная валидация)

**Примечание:** Основные данные берутся из GameModel.Search, дополнительные запросы не требуются.

### 9.3. UnitService

Использовать методы:
- `UpdateUnitDetectionLevel(unitID, level)` - для обновления DetectionLevel кораблей
- `GetEnemyUnitsInHex(gameID, hexID, enemySide)` - для поиска вражеских юнитов

### 9.4. TaskForceService

Использовать методы:
- `UpdateTaskForceDetectionLevel(tfID, level)` - для обновления DetectionLevel ТФ
- `GetEnemyTaskForcesInHex(gameID, hexID, enemySide)` - для поиска вражеских ТФ
- `GetTaskForceUnits(tfID)` - для получения кораблей в ТФ

### 9.5. VisibilityService

Использовать методы:
- `SetUnitSighted(gameID, unitID, playerID, hexID)` - для сохранения видимости SIGHTED
- `SetUnitShadowed(gameID, unitID, playerID, hexID)` - для сохранения видимости SHADOWED


## 10. Обработка ошибок

1. **Ошибки при загрузке GameModel:**
   - Если GameModel не найден или поврежден → завершить фазу с ошибкой
   - Логировать критическую ошибку

2. **Ошибки при доступе к GameModel.Search:**
   - Если Search == nil или German/Allied == nil → инициализировать пустыми структурами
   - Если для конкретного гекса нет данных в Search → пропустить гекс
   - Продолжить обработку следующих гексов

3. **Ошибки при обновлении DetectionLevel:**
   - Логировать ошибку
   - Попытаться продолжить с остальными юнитами
   - Не прерывать всю фазу поиска

4. **Ошибки при обновлении видимости:**
   - Логировать предупреждение
   - DetectionLevel уже установлен, видимость можно синхронизировать позже

## 11. Тестирование

### 11.1. Позитивные сценарии

1. **Обнаружение с использованием GameModel.Search:**
   - GameModel.Search.Allied содержит гекс с Factor >= visibility_level
   - Союзники обнаруживают немецкий юнит → `SIGHTED` (AirSearch = 0)
   - Союзники обнаруживают немецкий юнит → `SHADOWED` (AirSearch > 0)

2. **Обнаружение ТФ:**
   - GameModel.Search.German содержит гекс с Factor >= visibility_level
   - Немцы обнаруживают союзную ТФ → `SIGHTED` или `SHADOWED` в зависимости от AirSearch

3. **Множественные обнаружения:**
   - Обнаружение нескольких юнитов в одном гексе → все получают одинаковый уровень
   - Уровень определяется по AirSearch в SearchHexData для гекса

### 11.2. Граничные случаи

1. **Видимость X:** фаза завершается сразу, маркеры не устанавливаются
2. **Недостаточно факторов:** гекс отсутствует в GameModel.Search или Factor < visibility_level
3. **Пустой GameModel.Search:** если мапа пустая → поиск не выполняется
4. **Отсутствие данных для гекса:** если гекс есть в GameModel.Search, но вражеских юнитов нет → логировать "нет контакта"

### 11.3. Интеграционные тесты

1. **Работа с GameModel.Search:**
   - Проверка чтения данных из GameModel.Search.Allied и GameModel.Search.German
   - Проверка корректности использования SearchHexData.Factor
   - Проверка использования SearchHexData.AirSearch для определения DetectionLevel

2. **Последовательность обработки:**
   - Проверка последовательности: союзники → немцы
   - Каждая сторона использует свой раздел GameModel.Search

3. **Завершение фазы:**
   - Проверка удаления маркеров `flight_path_search` в конце фазы
   - Проверка обновления видимости в таблице `unit_visibility`
   - Проверка синхронизации DetectionLevel для ТФ и их кораблей

4. **Актуализация данных:**
   - Проверка, что GameModel.Search содержит актуальные данные перед фазой поиска
   - Проверка, что пересчет SearchData выполняется при изменении позиций/маркеров

## 14. Связь с другими фазами

### 14.1. Фаза видимости (до фазы поиска)
- Устанавливает `visibility_level` и `is_fog`
- Сбрасывает обнаружения в туманных гексах и при видимости X

### 14.2. Фаза движения (после фазы поиска)
- `SHADOWED` → `SIGHTED` в конце фазы
- Сбрасывает обнаружения для юнитов, вошедших в туманные гексы

### 14.3. Фаза преследования (между движением и поиском)
- Переводит `SIGHTED` → `SHADOWED` при успешном преследовании
- Сбрасывает оставшиеся `SIGHTED` в `NONE` в конце фазы
