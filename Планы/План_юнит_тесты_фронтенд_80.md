## Примечания

1. **Не тестировать:**
   - Константы без логики
   - Типы и интерфейсы (TypeScript проверяет их)
   - Тривиальные getters/setters без логики

2. **Приоритет качества над количеством:**
   - Лучше меньше тестов, но качественных
   - Тесты должны быть понятными и поддерживаемыми
   - Тесты должны служить документацией

3. **Рефакторинг при необходимости:**
   - Если код сложно тестировать, возможно стоит его рефакторить
   - Выделение логики в отдельные функции для тестирования

4. **Документация:**
   - Тесты служат документацией поведения
   - Названия тестов должны быть описательными
   - Комментарии только когда необходимо
